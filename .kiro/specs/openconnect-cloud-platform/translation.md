# Translation capability status

Cloud translation remains unavailable until the NLLB worker has a functioning, offline real decoder and the gateway has authenticated admission, scoped privacy inspection, quota, fenced execution, settlement and output checks. The existing deterministic fake engine is for explicit non-production testing and must not be presented as translation service readiness.

For flat local NLLB bundles, readiness validation checks the weights SHA-256 and tokenizer SHA-256 against the manifest as well as the license policy. The worker does not advertise real translation or report real readiness while the decoder remains unimplemented, even when a bundle and neural libraries are present. The versioned cache has its own asset verification. A verified bundle alone does not establish that the model is safe, commercially licensed, or operational.

The decoder bundle resolver requires an explicitly active, fingerprint-matched versioned revision and verifies its complete declared assets, license policy and on-disk contents without fetching. Its initial supported layout is a single `model.safetensors` with declared model configuration, tokenizer and tokenizer configuration; undeclared, duplicate, linked or incomplete files are rejected. The offline decoder adapter uses local-only model loading, a pinned runtime version, explicit language tokens, bounded generation and serialized tokenizer access. A synthetic random M2M100 model verifies local loading and generation mechanics only; it does not establish translation quality. The adapter is not yet wired into worker readiness or execution, and the worker package does not yet provision its optional neural runtime. Mounting the verified cache read-only and controlling concurrent asset replacement remain deployment responsibilities.
