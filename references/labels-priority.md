# Labels and priority

Use only existing approved GitHub labels. Suggested taxonomy if labels are already installed: type:bug, type:feature, type:test, type:security, type:docs; priority:p0/p1/p2/p3; area:privacy, area:agents, area:hosting, area:sessions, area:transport, area:tools, area:blazor, area:typescript, area:liveui, area:navigator, area:workers, area:contracts. Never create labels automatically. If missing, write metadata inside the issue body.
P0: verified critical data compromise or total SDK security boundary failure. P1: serious interoperability/security or core SDK breakage. P2: significant correctness, DX or reliability gap. P3: bounded polish/docs proposal. Never inflate severity.
