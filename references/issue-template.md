# GitHub issue format

Title: [Area] Observable symptom or precise requested developer outcome

## Classification
Type: bug | feature | risk-validation | test-gap | documentation. Priority: P0 | P1 | P2 | P3. Package(s), client/worker surfaces, target framework and inspected baseline SHA.

## Evidence
Source links pinned to commit and relevant symbols, observed vs expected; distinguish SOURCE CONFIRMED, TEST EXECUTED, INFERRED, NOT VERIFIED. Reproduction or validation steps must be safe and executable; never invent results.

## Impact
Developer/user scenario, security/privacy impact, backwards-compatibility implications, consumer impact, affected environments and prerequisites.

## Acceptance criteria
Concrete checked behaviors, negative/error cases, regression tests, compatibility tests, docs/semver/migration obligations as relevant.

## Related work
Links to equivalent closed/open issues, merged/open PRs, and reasons candidate is not a duplicate. No sensitive payloads or exploit instructions.
